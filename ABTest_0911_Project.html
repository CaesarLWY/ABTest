a-3. Are these betas time varying?

Since these betas represented regression coefficients in the model, they are affected by the return time series data and the modeling periods. So they are indeed time varying.

b. What regression technique can one employ to find more stable beta? How do your results change?

Since betas and the results of regression are easily affected by the time series data used for training model, either adopting AR/Adaptive/Regime types of beta modeling should improve the stability.

Consider AR-type model, we use autoregressive model to assume historical beta follow a distribution with characteristic of reverting, then solving techniques like Kalman Filter can be adopted on. In terms of adaptive modeling, we increase the weights of closer-date return, in order to better capturing and reflecting the latest fluctuations in the return time series data. As for regime-type model, we can carefully split the time series return data by other facets, either by statistical methodology like HMM to recognize different regimes, or by economic rationale and related observed indicators to classify the data to different scenarios, then we used different kinds of smoothing and predicting model in different regimes.

The original version of static betas measurement should be good for attibutions and posterior analysis. However, when it comes to priori prediction and analysis, time varying/regime depending betas measurement should be more beneficial in constructing portfolios. The time varying results should be less volatile since it contains smoothing in the modeling, and the regime depending results should demonstrate only less volatile in the same states, the change should be more dramastic if we compare results in different regimes.

from scipy.cluster.hierarchy import linkage, dendrogram, fcluster
from scipy.spatial.distance import squareform
from sklearn.metrics import silhouette_score


distance_matrix = np.sqrt(0.5 * (1 - corTab))
condensed_distance = squareform(distance_matrix)
Z = linkage(condensed_distance, method='ward')

best_score=-1
best_k= 2
for k in range(2,7):
    test_labels= fcluster(Z, t=k, criterion='maxclust')
    score= silhouette_score(distance_matrix, test_labels, metric='precomputed')
    
    if score> best_score:
        best_score= score
        best_k= k

print(best_k)
final_clusters= fcluster(Z, t= best_k, criterion='maxclust')

group_results = pd.DataFrame({'Industry': corTab.columns, 'Cluster': final_clusters})
print(group_results.sort_values('Cluster'))

We can also project the industry correlation and distance onto other coordinate system, generally speaking, we can see from the plot that industries fall into two distinct clusters.

The clusters will be changing as time varies. If we adopt walk forward algorithm, instead of using dataset from the whole period, we only look back the data from certain days ago to train the model, the result should be different but still in consistent with the latest market structure, and the time-varying clusters difference can be demonstrated once the clustering follow rolling-type analysis.

Either supervised or unsupervised algorithms in machine learning area can attain similar groupings, but the main reason of using unsupervised algorithm, hierarchical clustering, lies in the absence of given parameters. If other algorithms adopted like K means or KNN, we need to specify a parameter to tell the model to classify the data into K groups or K members in a group, then the model will forcely split the data into the setting groups or members, this will result in very different industries but be classified as the same group sometimes. We used hierarchical clustering to allow the data reveal itself.

def MVO_w(cov_mat, constraints, num_assets):
    bounds= tuple((0,1) for _ in range(num_assets))
    init_guess= np.ones(num_assets)/num_assets
    
    optimized_result= minimize(
        port_var,
        init_guess,
        args=(cov_mat,),
        method='SLSQP',
        bounds=bounds,
        constraints= constraints, 
        tol= 1e-9
    )
    
    finalw1={}
    finalw2={}
    if optimized_result.success:
        optimal_weights= optimized_result.x
        sum_c1= 0
        for idx in ind_c1:
            weight= optimal_weights[idx]
            sum_c1+= weight
            if weight> 0.0001:
                finalw1[industries[idx]]= round(weight*100,4)
                
        sum_c2= 0
        for idx in ind_c2:
            weight= optimal_weights[idx]
            sum_c2+= weight
            if weight> 0.0001:
                finalw2[industries[idx]]= round(weight*100,4)
    return finalw1, finalw2
